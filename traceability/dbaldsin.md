## Requirement changes

| ID | Original requirement (P4A) | Revised requirement | Why it changed |
|---|---|---|---|
| R5 | Verify a test claim against a recorded run and link to that run. | Verify a claim about a completed `bun test` run only when the recorded command output includes an unambiguous result summary. Show the recorded counts and a reference to the specific command result in Sources. | The terminal companion works from recorded command evidence, which can be truncated or lack a result. A specific command result in Sources gives users the evidence C-7 and S-7 asked for. Limiting the requirement to an unambiguous summary from one runner gives the verification rule a checkable boundary. |
| R6 | Show unknown delivery after lost confirmation and check for prior delivery before retrying. | If delivery cannot be confirmed, show it as uncertain and offer Check delivery. Look up the original destination and message ID before considering another send. Checking never submits a second instruction. | A missing message can still be queued for promotion. A lookup alone cannot distinguish that case from a send that never reached the server. Checking the original message preserves the control and duplicate prevention requested in C-8 and S-8. |

I kept R1–R4 because the preview, Chat, project notebook, and layout expose observable state for each check. R7 has a reproducible write-failure scenario and R8 has a concrete example whose values and explanation can be checked against the prepared change.

## Test triage

R2 failed when Chat was one row below the top before opening the preview. Back restored the draft but jumped to the newest reply, row 33 in the shrunk case. The preview unmounted the Chat scrollbox, so its replacement started at the bottom. The overlay now records the scroll offset before opening the preview and restores it once the Chat scrollbox has been measured.
